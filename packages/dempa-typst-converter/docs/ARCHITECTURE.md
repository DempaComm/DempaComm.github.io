# 設計

## 処理境界

```text
LaTeX原稿
  ↓ Tylax（外部ツール）
tylax.raw.typ
  ↓ correction.py（構文成立前の明示的補正）
main.typ
  ↓ dempa-style.typ（組版だけ）
Typst PDF
```

`correction.py` は壊れたTypst構文を扱う。`dempa-style.typ` は構文として成立した文書の見た目と
共通部品だけを扱う。この境界を越えて、スタイルでLaTeX文字列を解釈したり、補正器で紙面の
見た目を決めたりしない。

## 安全原則

- 入力ファイルを上書きしない。
- 規則はID、説明、置換回数を持つ。
- 意味が一意に決まらない変換は規則へ追加しない。
- 未知のLaTeX命令、対応しない定理境界、重複ラベル、未解決参照は成功扱いにしない。
- 補正後も手動確認必須かつ自動公開不可と記録する。
- 実原稿ではなく、新規作成した最小例で回帰テストを作る。

## 今後の実装順

1. `\neq` 以外の一意な数式トークンを、個別テスト付きで追加する。
2. 複数原稿で定理境界、共有番号、ラベル参照の変換結果を検証する。
3. 診断位置を行・列付きで報告する。
4. 証明終端記号がない原稿の安全な構造解析方法を検討する。
5. 複数原稿で同じ結果を得られた規則だけ安定APIへ昇格する。

一般的なTylaxの不具合は、最小再現例を作って上流Issueへ報告する。Tylax本体の恒久フォークは
このパッケージの前提にしない。
