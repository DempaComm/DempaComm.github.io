# ローカル管理画面の使い方

普段の原稿修正には、`dempa-cc-by-4` のローカル管理画面を使います。
本文はVS Codeで編集し、管理画面では保存した修正の検査・登録と公開の準備をします。
`数識電収.code-workspace` と同じフォルダです。別コピーの `DempaComm.github.io` では起動しません。

## 管理画面を開く

1. Macの「ターミナル」またはVS Codeのターミナルを開く。
2. 次の2行をコピーして実行する。

```sh
cd /Users/yoshitoishiki/Documents/Codex/dempa/dempa-cc-by-4
python3 scripts/paper_tool.py local-admin
```

3. ターミナルを開いたまま、ブラウザで [管理画面を開く](http://127.0.0.1:8765/)。

画面を使い終えたら、起動したターミナルで `Ctrl+C` を押すと停止できます。
次回は、同じ2行で起動してください。

VS Codeでは「ターミナル」→「タスクの実行」→「数識電収: ローカル管理画面を起動」からも起動できます。

## 原稿を直して公開するまで

### 1. 原稿を編集・保存し、PDFを確認する

`dempa-cc-by-4/papers/記事番号/` にあるTeXなどをVS Codeで修正します。
修正を保存し、PDFを作り直して全ページを確認してください。

### 2. 管理画面で記事を選ぶ

「修正した記事」から対象を開きます。見つからないときは、記事名・記事番号・ファイル名で検索できます。
保存直後は「保存した変更を再確認」を押してください。

### 3. 「修正したファイルを検査する」を押す

検査報告を読み、氏名やメールアドレスなどの指摘を確認します。
PDFの検査結果には全ページ画像が出ます。TeXを直した場合は、手元で作り直したPDFも全ページ確認します。

### 4. 修正理由を書いて登録する

検査結果の下で、修正理由を書きます。例：「定理2の誤植を修正した」。
自分で確認した2項目にチェックを入れ、「この修正を登録して検査する」を押します。
修正の登録と全体検査が行われ、古くなったHTML版は控えを残して外されます。

### 5. HTML版が必要なら作り直す

HTML版は、ブラウザで本文を読むためのページです。
「この記事の続きを開く」→「確認用のHTML版を作る」と進みます。
できたHTML版をPDFと見比べて、数式・図・参照番号・本文を確認してください。
問題がなければ確認欄にチェックし、「このHTML版を公開用に登録する」を押します。
PDFだけで公開する記事は、この手順を飛ばせます。

### 6. サイト全体の変更点を確認する

修正したすべての記事の作業が終わったら、一覧の「公開前の確認」へ進みます。
「公開前の検査と変更点の確認」を押し、表示された変更が今回意図したものだけか確認してください。
理由と確認チェックを入れて「確認した変更を記録する」を押します。
前回確認した内容と同じなら、追加の変更記録は不要です。

### 7. 最後に公開する

管理画面での作業は、このMacの中での公開準備です。
実際にサイトへ反映するには、意図したファイルだけをGitで記録（commit）して送信（push）します。
VS Codeで操作するか、Codexに対象の記事を添えて「この修正をcommitしてpushして」と依頼できます。
現在の作業ブランチは `codex/site-search-navigation` です。このブランチへのpushは保存・共有のための操作です。
確認済みの変更を `main` へ統合し、GitHub Actionsのbuild・deployが成功したら、公開サイトで修正を確認してください。
コマンドでの手順は [原稿修正の簡単手順](EDITING_WORKFLOW.md#4-コミットしてpushする) を参照してください。

## 途中で困ったとき

- **管理画面につながらない**：上の起動コマンドを実行し、ターミナルを開いたままにします。
- **`Address already in use` と出る**：別の作業用コピーの管理画面が動いている可能性があります。起動元のターミナルが分かる場合は `Ctrl+C` で停止し、上の2行で起動し直します。停止したくない場合は `dempa-cc-by-4` で `python3 scripts/paper_tool.py local-admin --port 8766` を実行し、[別ポートの管理画面](http://127.0.0.1:8766/) を開きます。
- **管理画面を更新したのに表示が古い**：起動中のターミナルで `Ctrl+C` を押し、起動し直してからブラウザのページも更新します。再起動で一時リンクが切れた場合は、必要な検査からやり直します。
- **検査のあとで原稿を再修正した**：保存して記事の画面に戻り、「修正したファイルを検査する」からやり直します。
- **検査で止まった**：画面の説明と「検査の詳細」を確認し、分からなければCodexに表示内容を伝えます。修正の登録後に止まった場合は、その旨が表示されます。
- **新しい文献ファイルや図を追加した**：別途登録が必要です。Codexに記事番号と追加したファイル名を伝えてください。

画面内の「使い方」からも、手順を確認できます。

## 表示の意味と実装上の境界

- 「修正の確認待ち」は、登録済み原稿と内容が変わっている状態です。
- 「保存済みの変更あり」は、登録済みファイルの内容は同じでも、追加ファイルや記事情報などにGitへ記録していない変更がある状態です。公開サイトへの反映状況はこの表示だけでは分かりません。
- 詳しいGitの変更一覧と処理ログは、折りたたみ欄に表示します。
- 管理画面は `127.0.0.1` だけで待ち受け、変更操作には起動ごとの確認トークンを要求します。
- 原稿本文の編集、自動の目視承認、commit・pushは行いません。
- 新しい文献ファイルや図など、未登録のファイルの追加は別途登録が必要です。
- 修正の登録とHTML版の登録は、既存の個人情報確認・公開差分承認を維持しています。
