  - TikZをインラインSVGへ変換し、SVG数と危険要素を検査する機能を追加した。

## 機能追加候補
- LaTeXML HTML版を保守する。
  - 「自動変換・未目視」のHTMLを元PDFと順次比較し、確認済み版へ昇格する方法を整える。
  - 新しいTeX原稿の追加時にもHTML変換を安全に実行できる手順を文書化する。
  - 複雑なTikZライブラリや独自BSTで新しい差異が見つかった場合は、元TeXを変更せず変換処理側で対応する。
- TeX原稿からTypstへの変換を実験する。
  - TylaxとPandocを隔離実行する `typst-trial` コマンドと4分類設定を追加した。
  - 元原稿を一時領域へコピーし、変換結果はGit管理外の `_experiments/` だけに生成する。
  - 2026-07-28に4分類を初回変換し、Pandoc 4件とTylax 3件で `.typ` を得た。
  - 初回出力は参照、入れ子数式、独自命令の問題で未補正コンパイルに失敗したため、
    単純なTeXから変換後補正の安全な範囲を検討する。
  - Tylax生出力を上書きせず、明示的な補正とJSON報告を行う公開用パッケージ雛形を
    `packages/dempa-typst-converter/` に追加した。
  - `dempa-style.typ`、導入・変換・独立公開手順、人工的な最小例をパッケージ内へ分離した。
  - `\neq` に加え、対応する境界を持つ定理構造、ラベル、参照、終端記号付き証明を
    固定番号ではなくTypstの番号付き構造として復元する補正を追加した。
  - 前回の「素数の無限性」のTylax生出力を自動補正し、A4・1ページのPDF生成と紙面を確認した。
  - 次の練習記事に「代数学の基本定理2」を選び、事実・補題、任意題名、複数証明、手書き
    参考文献を補正した。A4・2ページのPDF生成と全ページ紙面を確認した。
  - 補正後の実コンパイル検査をCLIへ組み込み、構文エラーを見逃して成功扱いする穴を塞いだ。
  - 「順序数の位相的重み」で数字ラベルと古い証明記法、独自命令を分類した。数字ラベル、
    単一行の古い証明、`\card`、文書外コメント混入、番号なし表示数式を補正し、A4・1ページの
    PDFを確認した。
  - JSON報告へ生のTylax入力を基準とする行・列付き診断を追加した。従来の停止理由を維持し、
    未対応命令、残存ラベル、未解決参照、境界マーカーをCLIからも位置付きで確認できる。
  - 原稿全体の変換は、Apache-2.0で公開されているTylaxを第一候補にする。
  - PandocによるLaTeXからTypstへの変換を比較基準として試す。
  - 数式変換の補助候補として、Apache-2.0のMiTeXとtex2typstを比較する。
  - 「単純なTeX」「図や参照を含むTeX」「複雑なTeX」「BibTeXを使う原稿」の4分類で変換結果を比較する。
  - 日本語、独自マクロ、定理環境、相互参照、BibTeX・独自BST、TikZ・図版の保持状況を確認する。
  - 元のTeXは変更せず、変換した `.typ` を派生ファイルとして別保存する。
  - 変換結果をTypstでコンパイルし、元のPDFとの内容・数式・参照・図版の差を人間が確認する。
  - 十分に変換できた原稿だけTypst版の公開候補とし、失敗時は現在のPDF・TeX公開を維持する。
- SATySFiへの変換は独立した実験として継続する。
  - `packages/dempa-satysfi-converter/` にPandoc AST経由の最小変換器、共通スタイル、人工例、
    回帰テストを実装した。「素数の無限性」は隔離領域で警告なしPDF生成まで確認済みである。
  - 同じ代表4分類を使い、日本語、数式、定理環境、参照、文献、図版を比較する。
  - 自動変換率だけでなく、型検査の利点と変換後ソースの人間による保守性を評価する。
  - Typst試験と同様、元TeXを変更せず、派生物は隔離領域で管理する。

## 次期リファクタリング計画（クレジット回復後）

以下を順番に実施する。各段階で既存テストと公開物基準を通し、公開URL、`paper.json`、
操作コマンド、原稿保護規則を変えない。大きな一括変更にはせず、段階ごとにコミット可能な
状態へ戻す。

1. 検査処理の重複を解消し、高速モードを追加する。（完了）
   - `check-all` を8工程から4工程へ統合し、SHA、カタログ、リンクは安全な `stage` の内部で一度ずつ検査するようにした。
   - 表示された工程時間の合計は約16.3秒から約10.6秒へ短縮した。
   - `check-paper <記事番号>` を追加し、対象記事の承認済みSHA、個人情報検査記録、`keywords.txt`、必要なTeXビルドだけを確認できるようにした。
   - GitHub ActionsではTeXビルド前のSHA・カタログ早期検査を残し、`stage` 後の二重リンク検査だけを削除した。
   - 成功時は要約だけ、失敗時は原因の詳細を表示する。コミット前の完全検査では、SHA保護、個人情報、リンク、公開物比較を引き続き必須とする。
   - 追加整理として、GitHub Actionsの生成PDFをキャッシュし、変更された原稿だけを再ビルドするようにした。
   - 定理等のHTML抽出、読書経路、原稿能力情報を一回の公開処理内で共有し、同じHTMLを三回解析しないようにした。
   - 全テストの範囲は維持し、独立したテストモジュールを最大4本並行で実行する。ローカル計測では約5.6秒から約3.4秒になった。
   - リンク検査は汎用HTML全文解析から `id`・`href`・`script src` 専用スキャナーへ置き換えた。派生情報共有と合わせ、サイト生成はローカル計測で約18秒から約5.8秒になった。
2. `dempa_site/conversion/latexml.py` を責務別に分割する。（完了）
   - TeX正規化を `latexml_normalization.py`、PDF・TikZ図版を `latexml_graphics.py`、警告・HTML安全性判定を `latexml_analysis.py` へ分けた。
   - `latexml.py` は対象選択、外部コマンド実行、結果集約を担当する。既存の内部関数名は再公開している。
   - 対象ごとの一連処理も、コマンド構築、一時ソース準備、変換実行、HTML検査・後処理、結果レコード作成へ分割した。正規化は処理順と記録名を一つの表で管理し、変換・公開試験14件で互換性を確認した。
3. サイト機能の登録方法を統一する。（完了）
   - 読書経路、系譜、関係図、探索ページを `features/registry.py` の一か所へ登録した。
   - 四機能を必須機能として個別の一時領域で生成し、失敗時は以前の公開先を保持する。任意機能の隔離、無効化、衝突防止も同じ実行機構を使う。
4. `scripts/paper_tool.py` の内部を用途別に分割する。（完了）
   - 原稿検査、原稿変更、インポート、サイト生成、LaTeXMLの実処理は各 `dempa_site` モジュールへ置き、CLI本体を薄い接続層とした。
   - 約230行の引数定義を `dempa_site/cli_parser.py` へ分離した。利用者が実行するコマンド名と使い方は変更していない。
5. 生成済みファイルの扱いを整理する。（低優先度として延期）
   - Gitに保存しているトップページ・`keywords.txt` と、毎回生成するアーカイブ・サイトマップの方針を比較する。
   - 差分をGitで確認できる利点を残しつつ、重複生成や古さの検査を一か所へ集約する。
   - 方針変更の利益が小さい場合は現状維持とし、無理に統一しない。
6. HTML版メタデータを整理する。（完了）
   - `html_version` と `alternate_html_versions` を、主HTMLを先頭に置く単一の `html_versions` 配列へ統合した。
   - HTML版を持つ169記事を新形式へ移行し、LaTeXML公開処理も新形式だけを書き出すようにした。
   - 古い作業ブランチや非常用手順から取り込めるよう、旧形式の読込み互換性は当面残す。新旧フィールドの混在は検査で拒否する。
7. `styles.css` の保守方法を整理する。（低優先度として延期）
   - 共通レイアウト、原稿カード、探索ページ、関係図、LaTeXML、スマートフォン対応へ分割する案を試す。
   - 公開時に一つへ結合する場合と、現在の単一CSSを維持する場合の複雑さ・容量・キャッシュを比較する。
   - 分割の利益が小さければ現状維持とする。この項目の優先度は最も低い。

完了条件は、全テスト成功、公開前検査成功、公開物基準に意図しない差分がないこと、
既存の原稿修正手順がそのまま利用できることである。
